The Problem: When One Agent Fails

Let’s look at a realistic task:

“Research AI trends in 2026, evaluate the most important ones, and write a professional report with sources.”

Try this as ONE agent:

  • It must:
    • Search
    • Evaluate sources
    • Decide importance
    • Write clearly
    • Cite correctly

👉 This usually results in: - Weak sourcing
- Hallucinated facts
- Mixed reasoning + writing
- No clear failure point

WarningKey Insight

A single agent must do everything in one context window.

This creates: - Cognitive overload
- Poor specialization
- No separation of concerns

The Real Use Case: Research Pipeline System

This is where multi-agents shine.

Real systems (like production research tools) use a structure like this:

  • Planner Agent → breaks task into subtopics
  • Research Agents → gather information (parallel)
  • Analyst Agent → evaluates and compares findings
  • Writer Agent → produces final report

This pattern is widely used because: - Tasks are naturally separable - Work can be parallelized - Each agent has focused context oai_citation:0‡Anthropic

Why This CANNOT Be One Agent

If you try to force this into one agent:

Problem Why it Happens
Hallucinated sources No separation between retrieval and writing
Weak reasoning Mixing analysis + writing
Context overload Too many responsibilities
No debugging You don’t know which step failed

Guided Coding: Real Multi-Agent System

We will build:

👉 A Research Pipeline System

  • Research Agent
  • Analyst Agent
  • Writer Agent
  • Manager Agent (controls everything)

Step 1: Create Specialized Subagents & Tools

We are going to include a simple local folder reader that can read data inside a folder called “student data” you can change this if you would like. You will have to create this folder and add files to it for the tool to work.



# Add tools at the end of this block

from langchain.agents import create_agent
import os
from dotenv import load_dotenv
from langchain.tools import tool

load_dotenv()

# Optional: print to verify (should NOT be None)
print(os.getenv("GEMINI_API_KEY"))


from langchain.tools import tool


STUDENT_DATA_DIR = "student_data" # this is where the directory is


@tool
def read_student_files(query: str) -> str:
    """
    Reads all files in student_data/ and returns their contents.
    The query is ignored for now (simple version).
    """
    if not os.path.exists(STUDENT_DATA_DIR):
        return "student_data folder not found."

    all_text = []
    for fname in os.listdir(STUDENT_DATA_DIR):
        path = os.path.join(STUDENT_DATA_DIR, fname)

        if not os.path.isfile(path):
            continue

        try:
            with open(path, "r", encoding="utf-8", errors="ignore") as f:
                content = f.read()
            all_text.append(f"\n--- {fname} ---\n{content}")
        except Exception as e:
            all_text.append(f"\n--- {fname} ---\nERROR: {e}")

    return "\n".join(all_text)

These are very simple agents. They just call the LLM with a specific system prompt and tools. They could be made much more complex with memory, tool use, etc. but this is the basic structure.




# Research Agent
research_agent = create_agent(
    model="google_genai:gemini-2.5-flash",
    system_prompt="""
You are a research agent.

ONLY gather facts.
- No opinions
- No summaries
- Return bullet points
""",
    tools = [read_student_files] # add real tools here
)

# Analyst Agent
analysis_agent = create_agent(
    model="google_genai:gemini-2.5-flash",
    system_prompt="""
You are an analyst.

Take research and:
- Identify key insights
- Compare ideas
- Rank importance
"""
)

# Writer Agent
writer_agent = create_agent(
    model="google_genai:gemini-2.5-flash",
    system_prompt="""
You are a professional writer.

Turn analysis into:
- Clear report
- Well structured
- Professional tone
"""
)

Step 2: Wrap as Tools

Now we wrap each agent as a tool that the manager can call. This keeps their contexts separate and allows the manager to control the flow.




@tool
def do_research(query: str) -> str:
    """Gather raw information"""
    result = research_agent.invoke({
        "messages": [{"role": "user", "content": query}]
    })
    return result["messages"][-1].content


@tool
def do_analysis(data: str) -> str:
    """Analyze research"""
    result = analysis_agent.invoke({
        "messages": [{"role": "user", "content": data}]
    })
    return result["messages"][-1].content


@tool
def do_writing(data: str) -> str:
    """Write final report"""
    result = writer_agent.invoke({
        "messages": [{"role": "user", "content": data}]
    })
    return result["messages"][-1].content

⸻

Step 3: Create Manager Agent

Notice how the manager agent has the subagents in their tools. The system prompt is very important for the manager to understand what its supposed to do.

manager = create_agent(
    model="google_genai:gemini-2.5-flash",
    system_prompt="""
You are a manager coordinating a research pipeline.

Steps:
1. Call do_research
2. Pass result to do_analysis
3. Pass result to do_writing

After do_writing finishes, RETURN ONLY the exact text output from do_writing as the final answer.
Do not add any extra commentary or status text.
""",
    tools=[do_research, do_analysis, do_writing]
)

⸻

Step 4: Run It

response = manager.invoke({
    "messages": [
        {"role": "user", "content": "Go into student files and write a study guide based on the contents."}
    ]
})

print(response["messages"][-1].content)

WarningBig Tip for Searching: Add Search tool

This tool would make your agent actually use the web and get real information instead of hallucinating.

from langchain.tools import tool

@tool
def search_web(query: str) -> str:
    """Search the web for current information"""
    # This would call a real API like Tavily or SerpAPI
    return "Search results for: " + query

Then make these changes to one of your subagents

research_agent = create_agent(
    model="google_genai:gemini-2.5-flash",
    tools=[search_web],
    system_prompt="You are a research agent. ALWAYS use search_web for current info."
)

Note

Key Takeaways • Multi-agents are NOT for simple tasks • They are for: • Multi-step workflows • Specialized roles • Parallelizable work • The best use case: 👉 Pipelines (research → analyze → write) • Subagents work best when: • Roles are clear • Context is isolated • Flow is structured
